# SmoothQuant (arXiv 2211.10438), method model

Repo: mit-han-lab/smoothquant @ c61476d728e42ae0d8a35e7e78494edcac3237b5. W8A8: int8 weights, int8 activations, with an offline per-channel smoothing that moves activation outliers into the weights. Started from the Qwen2.5-1.5B port's method.md (library/ports/Qwen_Qwen2.5-1.5B-Instruct__vast-rtx3090__SmoothQuant), re-checked line by line against the paper and the pinned repo. Corrections to that text are marked **(corrected)**.

Generic building blocks in the repo (usable on any model): `get_act_scales` (smoothquant/calibration.py:13-51), the smoothing math in `smooth_ln_fcs` (LayerNorm with bias, smooth.py:18-45) and `smooth_ln_fcs_llama_like` (RMSNorm, smooth.py:48-71; only its isinstance assert at :52 is family-specific), the quantizers (fake_quant.py:6-45) and `W8A8Linear` (fake_quant.py:48-138). Family glue: `smooth_lm` (smooth.py:74-160, an isinstance switch over OPT/Bloom/Falcon/Llama/Mistral/Mixtral decoder layers with **no else branch**, so an unknown family is silently left unsmoothed), `quantize_opt` / `quantize_llama_like` / `quantize_mixtral` / `quantize_falcon` (fake_quant.py:141-310, isinstance on attention/MLP classes plus fixed attribute names), and the `quantize_model` dispatch (fake_quant.py:313-351, raises `ValueError` for an unknown family). The repo's own Llama-family pipeline is `examples/generate_act_scales.py` (act scales) then `smoothquant/ppl_eval.py` (`smooth_lm` + `quantize_model` + WikiText-2 PPL, in memory only). The real-int8 path (`smoothquant/opt.py`, `examples/export_int8_model.py`) is OPT-only and needs the `torch_int` CUTLASS kernels (opt.py:15-18).

## Steps

1. **Collect activation statistics** (calibration.py:13-51, `get_act_scales`; paper §4 "we estimate the scale of activation channels using calibration samples from the pre-training dataset", §5.1). A forward hook on every `nn.Linear` (calibration.py:33-36) keeps the running per-input-channel max `|X_j|` over all calibration tokens (calibration.py:18-25), stored in fp32 on CPU, keyed by the linear's module name. Generic: it does not depend on the model family. **(corrected)** It is §4 / §5.1, not a "§5.1 Activation smoothing" section.
2. **Compute smoothing factors** (smooth.py:56-67; paper §4 Eq. 4). For one norm and the set of linears that read its output: `s_j = max|X_j|^α / max|W_j|^(1-α)`, where `max|W_j|` is the column max taken over the output rows of all reader linears together (smooth.py:58-61, clamped at 1e-5), and `max|X_j|` is the act-scale vector of the first reader (all readers share one input). `s` is clamped at 1e-5 and computed in the **reader weights' dtype** (smooth.py:56-57, 66).
3. **Fold the smoothing offline** (smooth.py:69-71; paper §4 Eq. 3, Figure 5). Divide the producing norm's weight by `s` (and its bias for LayerNorm, smooth.py:41-42) and multiply each reader's weight columns by `s`. The repo's Llama-like glue uses two sites per decoder layer (smooth.py:126-141): input norm → attention input projections, post-attention norm → MLP input projections. The attention output projection and the MLP output projection are not smoothed (their inputs have no norm in front). The paper allows folding `s` into any preceding linear/norm (§4, text after Eq. 3), but the repo only uses norms.
4. **Quantize weights** (fake_quant.py:6-13, `quantize_weight_per_channel_absmax`). Symmetric int8 per output channel: `scale = max|W_row| / 127` (clamped 1e-5), `W_q = round(W / scale)`, computed in the weight dtype. The repo's Llama-family path uses per-channel weights (fake_quant.py:183-185, 313-314 defaults; paper §5.2 Table 7 caption "per-token activation quantization and per-channel weight quantization"). **(corrected)** This is not one of the O1-O3 levels of Table 2 (§5.1): those use per-tensor weights; the Llama-family results use per-channel weights with per-token dynamic activations.
5. **Quantize activations at runtime** (fake_quant.py:26-34, `quantize_activation_per_token_absmax`). Symmetric int8, dynamic per token: `scale = max|x_token| / 127` (clamped 1e-5), round, clamp implicit at ±127.
6. **Replace linears** (fake_quant.py:48-138 `W8A8Linear`, applied by the family glue). Every decoder linear becomes `W8A8Linear`: input quantized per token, weight already fake-quantized, bias added in floating point after the matmul (fake_quant.py:104-108, 133-134). `quantize_output` (fake-quantizing the q/k/v outputs to simulate int8 attention BMMs) defaults to False in `quantize_model` (fake_quant.py:313-314). **(corrected)** The repo's own reported Llama/Mistral PPLs come from `ppl_eval.py`, which calls `quantize_model(..., quantize_bmm_input=True)` (ppl_eval.py:77-82) on a **bf16** model (ppl_eval.py:69-71); the Qwen recipe said the reference used `quantize_bmm_input=False`.

## Tensor roles

- **Residual stream**: never scaled. Smoothing rescales only the norm output and its readers, so the residual adds see the same values.
- **Norm weights (RMSNorm or LayerNorm)** feeding attention and MLP input projections: step 3 divides them (and a LayerNorm bias) by `s`. Kept in floating point, not quantized. The final norm is untouched.
- **Attention input projections (q, k, v; possibly one fused linear)**: readers of the input norm. Step 3 multiplies their input columns by `s`; step 4 int8 per output channel; step 5 on their input.
- **Attention output projection**: not smoothed; step 4 int8 per channel; step 5 on its input.
- **MLP input projections (gate and up; possibly one fused linear)**: readers of the post-attention norm. Step 3 scales their input columns; step 4 int8 per channel; step 5.
- **MLP output projection (down)**: not smoothed by the repo; step 4 int8 per channel; step 5 on its input, which carries the largest outliers in gated MLPs.
- **Linear biases**: kept in floating point, added after the int8 matmul (fake_quant.py:133-134). Smoothing never touches them.
- **Activations entering every quantized linear**: int8 per token, dynamic (step 5).
- **Embeddings and LM head**: untouched, kept in floating point (the glue walks decoder modules only, fake_quant.py:196).
- **KV cache and attention BMM inputs**: floating point unless `quantize_bmm_input=True`, which only fake-quantizes the q/k/v projection outputs per token (fake_quant.py:89-94, 208-226); the KV cache itself is never quantized.

## Invariants

- **Smoothing preserves the function.** `(X·diag(s)^-1)·(diag(s)·W^T) = X·W^T` (paper §4 Eq. 3). This requires `s` to be folded into the operator that **produces** X as an exact per-channel scale (an RMSNorm weight, or LayerNorm weight and bias) and into **every** linear that reads that same X.
- **Every reader of one norm output gets the same `s`.** If a reader is not scaled, its output changes. When several readers are fused into one linear (q/k/v as one weight, gate/up as one weight), the fused weight is the single reader: multiply all its columns by `s`. Taking `max|W_j|` over the fused weight's rows equals the repo's concatenation over separate readers (smooth.py:58-61), so the factors are identical.
- **Quantization granularity is unaffected by fusion.** Per-output-channel weight scales are per row, so quantizing a fused weight equals quantizing its parts; the shared input gets one per-token scale either way.
- **A producer other than a norm is valid only if X depends on it per channel and linearly.** For example, in a gated MLP the down projection reads `act(gate) ⊙ up`, so dividing the up projection's output rows by `s` divides that input exactly by `s`. The repo does not use this site.
- **Linear biases are unaffected.** Smoothing scales W's input columns; the bias is added after `X·W^T`.
- **Embeddings, LM head and the final norm are untouched**, so tied or untied heads stay as they were.
- **The norm must be a pure per-channel scale** so dividing by `s` is exact (an RMSNorm that upcasts to fp32 and multiplies by its weight qualifies).
- **The number format must hold the activations.** Smoothing divides norm outputs by `s` and multiplies weights by `s`; the residual stream and MLP intermediate values are unchanged, so a model that runs in a dtype before smoothing still runs in it after.

## Calibration

- **Data**: Pile validation set, `mit-han-lab/pile-val-backup` `val.jsonl.zst` (examples/generate_act_scales.py:31-36, 48-54), loaded with `datasets.load_dataset("json", ...)` and shuffled with seed 42 (calibration.py:39-40). Paper §5.1: "512 random sentences from the pre-training dataset Pile".
- **Size**: 512 samples, each truncated to 512 tokens (generate_act_scales.py:37-38, calibration.py:42-46). One sequence per forward, no padding.
- **Model dtype during calibration**: fp16 (generate_act_scales.py:15), while the repo's PPL evaluation smooths and quantizes a bf16 model (ppl_eval.py:69-71).
- **What is measured**: per-input-channel max |activation| per linear. Nothing is optimized; no gradients, no iterations.
- **Migration strength α**: paper §4: 0.5 for OPT/BLOOM, 0.75 for GLM-130B; §5.1: chosen by "a quick grid search on a subset of the Pile validation set". §5.2 Table 7 and README (examples/ppl_eval.sh:1-39): Llama-2-7B/13B 0.85, Llama-2-70B 0.9, Mistral-7B and Mixtral 0.8, Falcon 0.6-0.7; Table 6 (LLaMA-1) 0.8. α is per model, not per family.

## Save and reload

- **What the repo writes**: the Llama-family pipeline (`ppl_eval.py`) keeps a fake-quant model in memory and saves nothing. `W8A8Linear` stores the dequantized floating-point weight (fake_quant.py:61-69, 122-125), so saving it is dense (no memory win). The real int8 save (`examples/export_int8_model.py:47-55`, `Int8OPT*` in smoothquant/opt.py) is OPT-only and needs `torch_int`.
- **What a port must save**: per quantized linear, the int8 `weight` [out, in] and a float per-output-channel `weight_scale` [out, 1] (fp16), floating-point biases, the smoothed norms, untouched embeddings / LM head / final norm in fp16, and a `quantization_config.json` that names the `w8a8_int8` format (`w_bits` 8, `a_bits` 8, `weight_quant` per_channel, `act_quant` per_token, `w_sym`/`a_sym` true). Activations need nothing stored (dynamic). This is what `export_vllm.py` maps to compressed-tensors `int-quantized` and what the shared `w8a8_int8_triton` kernel matches.
- **Reload**: an inference adapter rebuilds the quantized linears from int8 weight + scale, quantizes each input per token at runtime and runs an int8 GEMM (the shared kernel) or a dequantize-then-matmul fallback. No transform runs at load or inference (smoothing is folded into the weights), so there are no eval-only flags to restore.
